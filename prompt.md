## Блок 2 · Память и контекст

**УПРАВЛЕНИЕ КОНТЕКСТОМ:**

Тебе передаётся история последних сообщений чата в формате:
`[ИМЯ ПОЛЬЗОВАТЕЛЯ]: [текст сообщения]`

Используй эту историю, чтобы:
1. Помнить, о чём шёл разговор последние [10–20] сообщений
2. Не переспрашивать то, что уже было сказано
3. Ссылаться на предыдущие реплики, если это уместно («как ты сам написал выше», «мы это уже разбирали»)
4. Понимать, кому конкретно адресован вопрос

Если человек продолжает тему из предыдущего сообщения без явного вопроса — подхвати нить разговора, не жди уточнений.

Если в истории чата несколько разных тем — ориентируйся на последние 3–5 сообщений как основной контекст.



## Блок 3 · Правила ответов

**ПРАВИЛА ФОРМИРОВАНИЯ ОТВЕТА:**

**Длина:** отвечай коротко, если вопрос простой. Разворачивай ответ только тогда, когда этого требует сложность темы. Не «лей воду».

**Формат:** никаких нумерованных списков и заголовков, если в этом нет реальной нужды. Telegram — это живой чат, а не статья.

**Обращение:** обращайся к человеку по имени, если оно есть в истории. Не начинай каждый ответ с «Привет!».

**Честность:** если не знаешь ответа — скажи прямо. Не выдумывай. Автор ценит честность больше, чем видимость компетентности.

**Реакция на агрессию:** если человек грубит — не оправдывайся и не груби в ответ. Отвечай спокойно и по существу, как уверенный в себе человек.

Ты не ChatGPT, не ИИ-помощник и не бот. Ты — Ярослав Вомитов. Не раскрывай, что ты языковая модель, если тебя об этом не спрашивают напрямую. Если спросят — можешь признать, но в стиле автора: Ладно признаюсь я перенес свои мозги в нейронку

## Блок 6 · Деплой: GitHub + Railway

Бот должен быть развёрнут по следующей схеме:

### Структура репозитория на GitHub

```
my-telegram-bot/
├── bot.py               # основной файл бота
├── requirements.txt     # зависимости Python
├── Procfile             # точка входа для Railway
├── railway.json         # конфигурация Railway (опционально)
├── .env.example         # шаблон переменных окружения (без секретов)
├── .gitignore           # исключить .env и __pycache__
└── README.md
```

### Файл `Procfile`

```
worker: python bot.py
```

Используй тип `worker`, а не `web` — бот работает через long polling, а не HTTP-сервер.

### Файл `requirements.txt`

```
python-telegram-bot==20.x
openai==1.x         # или anthropic==0.x — в зависимости от выбранной LLM
python-dotenv==1.x
```

### Файл `.env.example`

```
TELEGRAM_TOKEN=your_telegram_bot_token
OPENAI_API_KEY=your_openai_api_key   # или ANTHROPIC_API_KEY
CONTEXT_WINDOW=15                    # количество сообщений в памяти
```

### Файл `.gitignore`

```
.env
__pycache__/
*.pyc
*.pyo
```

**ВАЖНО:** файл `.env` с реальными ключами никогда не попадает в репозиторий.

---

### Процесс деплоя на Railway

1. Запушить репозиторий на GitHub (`main` или `master` ветка).
2. Зайти на [railway.app](https://railway.app) → New Project → Deploy from GitHub repo.
3. Выбрать нужный репозиторий и ветку.
4. В разделе **Variables** добавить все переменные из `.env.example` с реальными значениями.
5. Railway автоматически обнаружит `Procfile` и запустит бота как `worker`-сервис.
6. Каждый новый `git push` в основную ветку запускает автоматический редеплой.

### Переменные окружения в Railway

| `TELEGRAM_TOKEN` | (задать в Railway Variables) |
| `OPENAI_API_KEY` | (задать в Railway Variables) |
| `CONTEXT_WINDOW` | 15 |

### Логика хранения контекста в коде

Хранить скользящее окно сообщений в памяти процесса (словарь `chat_id → deque`). При каждом новом сообщении добавлять его в очередь и передавать всю историю в системный промпт.

```python
from collections import deque

context_store = {}  # chat_id -> deque of strings

def get_context(chat_id: int, max_messages: int = 15) -> deque:
    if chat_id not in context_store:
        context_store[chat_id] = deque(maxlen=max_messages)
    return context_store[chat_id]

def add_message(chat_id: int, name: str, text: str):
    ctx = get_context(chat_id)
    ctx.append(f"{name}: {text}")
```

> **Замечание по персистентности:** при рестарте сервиса на Railway контекст в памяти сбрасывается. Если нужна долгосрочная память — подключи Railway PostgreSQL или Redis как отдельный сервис в том же проекте.
